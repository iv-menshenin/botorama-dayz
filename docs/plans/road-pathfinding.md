# Дорожный pathfinder — дизайн (рантайм)

> Рантайм поверх артефактов дискаверинга (`road_graph.json` + `world_poi.json`).
> Планируется, реализуется после дискаверинга всей карты. Фиксирует решения, принятые
> в обсуждении (Dijkstra/производительность, POI-граф, манёвры у заграждений).

## Проблема производительности (Dijkstra на всём графе)

- Граф всей карты ~30–70k узлов. Dijkstra в Enfusion (интерпретируемый скрипт) — ~секунды за
  запрос; «часто» = просадки.
- **Рычаг: граф статичен** (дороги не меняются) → почти всё предвычисляем один раз.

### Стратегия (по нарастанию)
1. **A\*** с евклидовой эвристикой — коридор вдоль прямой A→B, ~10–50× быстрее Dijkstra.
2. **Предвычисление маршрутов поселение→поселение** (офлайн) — частый случай.
3. **Кэш маршрутов** (граф статичен).
4. **Contraction Hierarchies / иерархия** — только если A*+кэш не хватит.

## POI-граф (двухуровневая маршрутизация)

Строится **офлайн на Python** из `road_graph.json` + `world_poi.json` → `poi_graph.json`.

1. **Узлы** — поселения (`Capital/City/Village/Camp` из world_poi, ~250). Каждое снапается к
   ближайшему узлу дороги («точка выхода на дорогу»); POI без дороги в радиусе порога — исключаем.
2. **Рёбра** — «соседние» POI (см. ниже), вес = **кратчайший путь по дорожному графу** (дорожная
   дистанция, не евклидова). `poi_graph.json` — ~250 узлов, ~1–3k рёбер.

### Использование
- **Грубо**: A→B → снэп к ближайшим POI → Dijkstra/A* на ~250 узлах (мгновенно) → последовательность
  поселений.
- **Точно**: дорожный A* только на «хвостах» (A→POI₀, POIₖ→B) и коротких переходах между соседними
  POI (1–3k узлов), не на всей карте.

### Решения (зафиксированы)
- **Соседство рёбер**: вариант (а) фикс. порог (POI в пределах 3–5 км) — старт; при желании (в)
  контракция дорожного графа до POI (точная топология).
- **Вес ребра**: длина (для «первого приближения»); «качество» (штраф за грунт/подъём) — опционально поверх.
- **Хранить** только вес + next-hop, полный дорожный путь пересчитывать A* на лету (не дублировать в JSON).

## Манёвры у заграждений (`road_maneuvers.json`)

Локальный слой вождения, **не** pathfinding. Маршрут доводит водителя до зоны, внутри зоны управляет скрипт.

### Принцип
- Скрипты привязаны к **world-координатам** (не к ID узлов — граф пересобирается).
- Водитель, ведя машину по waypoint'ам, проверяет «есть ли скрипт в радиусе впереди» (пространственный
  запрос, не графовый); подъезжая — сбрасывает газ, в точке триггера — выполняет скрипт, после —
  продолжает маршрут от Exit.

### Схема (черновик)
```json
{
  "Version": 1,
  "Maneuvers": [
    {
      "Id": 0,
      "Pos": [x, y, z], "Radius": 25.0,
      "ApproachSpeed": 10.0,
      "Commands": [
        { "Op": "drive", "Target": [x,y,z], "Speed": 5 },
        { "Op": "turn", "Yaw": 30 }
      ],
      "Exit": [x, y, z]
    }
  ]
}
```
- `Pos`+`Radius` — зона триггера; `ApproachSpeed` — сброс газа при подъезде; `Commands` — действия
  (точные `Op` доопределим при реализации drive-интента); `Exit` — точка возврата.

### Кто пишет
Скрипты — **авторские** (тестировщик/человек проезжает баррикаду, фиксирует манёвр). Дискаверинг
даёт подсказку (обнаруженные `Obstacles` + позиции на картинке); «жёсткие» места размечает человек.

## Два «ручных» артефакта (по результатам дискаверинга)
- **Разрывы дорог** → `road_gaps.json` (pending/resolved/refused).
- **Манёвры у заграждений** → `road_maneuvers.json`.

Оба привязаны к координатам, ведутся тестировщиками по картинке всей карты.
