# Дорожный pathfinding — план (черновик для обсуждения)

Цель: pathfinder, который ведёт автомобиль ПО ДОРОГЕ (асфальт/грунтовка), а не по
пешеходному navmesh (который срезает по полям/лесам). Это ядро фичи вождения, не полировка.

## Вывод research (см. `docs/research/vehicles.md` → «Вождение: дорожный pathfinding»)

- **navmesh `PGAreaType.ROADWAY` ненадёжен**: в ванили это только cost-подсказка
  (никто не вызывает `SetCost(ROADWAY)`), на практике фрагментирован. Не детектор дороги.
- **`eAIRoadNetwork` (Expansion) — мёртвый код**: `Init()` закомментирован, `FindPath`
  пустой (нет A*/Dijkstra), реальный ИИ-водитель едет по navmesh. Портировать нельзя.
- **Детект дороги на лету есть**: `eAIRoadNode.ObjectIsRoad` — property `class=="road"`
  в geometry-LOD объекта.
- **`Game.SurfaceRoadY(x,z)`** — возвращает высоту дорожной поверхности (Y), но
  горизонтального «ближайшая точка на дороге» нет.

## Подход (MVP, ранжировано research'ем как минимальный жизнеспособный)

**Явная полилиния точек излома дороги (от пользователя) + Y-снэп.**

1. **Дорога = полилиния** `[точки излома]` — пользователь даёт координаты изломов дороги
   (вершины ломаной). Храним как данные (конфиг/файл, не разовые `Points` в сценарии).
2. **Снэп на дорогу**: старт (позиция машины) и финиш → ближайшая точка полилинии.
3. **Путь** = под-полилиния от стартовой до финишной точки — едем ВДОЛЬ дороги, без
   `FindPath` по пешей навмеш.
4. **Y-снэп**: каждая точка пути → `y = SurfaceRoadY(x, z)` — ехать ПО дорожной
   поверхности (не парить/не проваливаться).
5. Вождение — уже готово: waypoint-based интент + нативный привод + исправленный знак руля.

## Что нового относительно текущего waypoint-вождения

- Снэп старта/финиша на дорожную полилинию (сейчас точки задаём вручную в `Points`).
- Y-снэп на дорожную поверхность.
- Дорожная сеть как разделяемые данные (не per-scenario).

## Будущее (авто-поиск дороги, отложено)

- Авто-детект дорожных объектов через `ObjectIsRoad` + `GetObjectsAtPosition` →
  дорожный граф → A*/Dijkstra (когда понадобится «бот сам находит дорогу», а не едет по
  заданной полилинии).

## Открытые вопросы (обсудим, когда будут координаты)

1. Формат «точек излома»: просто список `(x,z)`, или структура (id дороги, направление,
   односторонность)?
2. Снэп старта/финиша: к ближайшей ВЕРШИНЕ полилинии или к ближайшей точке на СЕГМЕНТЕ
   (проекция на ребро)?
3. Нужны ли сейчас развязки/перекрёстки/односторонние дороги или одна дорога на первый раз?
4. Y-снэп: хватит `SurfaceRoadY`, или нужен `GetSurface(Roadway)` (тип поверхности:
   асфальт vs грунт)?

## Гипотезы `[нужно проверить]` (эмпирика на реальной дороге, после получения координат)

1. `SurfaceRoadY` ВНЕ дороги — возвращает terrain-fallback или что-то иное?
2. `GetObjectsAtPosition`/`SceneGetEntitiesInBox(ONLY_ROADWAYS)` — возвращает ли
   road-объекты на реальной дороге, какой практический радиус?
3. Memory-points (`LB/PB/LE/PE/…`) — есть ли у ванильных road-моделей (нужно для будущего
   графа по образцу Expansion).
4. `GetSurface(Roadway)` различает асфальт/грунт (для будущего выбора «по дороге»)?
