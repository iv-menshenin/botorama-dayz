# Соты (grid-объезд) + опорная точка вождения — план

Грид-объезд препятствий (соты) для широких/сложных заграждений, которые не берёт
коробка. Плюс перепроектирование опорной точки: водитель целится **носом** авто, а не
центром.

## Утверждённые решения

1. **Слои объезда**: коробка — для узкого/простого (быстро, 1 тик); соты — для
   широкого/сложного. Коробку ужесточить, чтобы при ЛЮБОЙ вероятности провала
   откатываться к сотам (не заводить водителя в тупик).
2. **Раскраска**: вертикальный райкаст сверху, высота НЕ выше среднего авто — ловим
   ствол/низкую крону (под высокой кроной машина едет), не крону. Если плохо —
   комбинировать (2 горизонтальных скрещённых + 1 вертикальная; возможно косые —
   лучше ловят деревья). Тестировщик пробует на живом сервере (райкастит).
3. **Маржа**: 1 клетка — «все соседи зелёные» даёт 3 зелёных в ширину = ширина авто.
4. **Длина территории (адаптивно)**: рисуем/раскрашиваем по 3 ряда сот за тик от
   машины вглубь маршрута; стоп, когда на дороге 10 рядов подряд все зелёные (по
   краям деревья не считаем). Альтернатива — райкаст-проверка 50 м вглубь (выяснить
   на живом сервере, что надёжнее).
5. **Сглаживание**: соты определяют ТОЛЬКО свободную территорию, НЕ форму движения.
   Траектория — плавная (string-pulling / скругление), водитель не дёргает руль.

## Опорная точка — нос, а не центр

Опорная точка (что «достигло» вейпоинт и куда целится руль) — **кончик переднего
бампера по середине ширины** (или между передних колёс): `nose = carPos + carDir *
DM_DRIVE_NOSE_OFFSET` (~2 м, пол-длины). Целить центром в вейпоинт — неверно:
вынос корпуса сильно отклоняет поведение при объезде.

- `toTarget = waypoint - nose` (руль целится носом).
- `dist = |toTarget|` — достижение вейпоинта (носом).
- `dot < PASSED_DOT` — «проехали мимо» тоже от носа.

## Фазы

1. **Опорная точка (нос)** — `dmBotIntent_Drive`: `DM_DRIVE_NOSE_OFFSET`, пересчёт
   `toTarget`/`dist`/`angle` от носа. (Малая, фундаментальная.)
2. **Соты** — `src/roads/4_World/Pathfinding/dmRoadHoneycomb.c`: асинхронный
   (раскраска по тикам) грид-объезд. Состояния `IDLE → COLORING → MARK_SAFE →
   PATHFINDING → DONE/FAILED`. Ячейка = 1/3 ширины авто (~0.66 м); территория —
   прямоугольник вдоль маршрута (ширина 3–4 ширины дороги, длина адаптивно).
   Красная = объект (даже частично) ИЛИ уклон > 15°; зелёная = чисто + твёрдо + полого.
   Путь — A* по «безопасным» (все соседи зелёные), сглаживание. Интент зовёт напрямую
   (зависимость core→roads уже перевёрнута).
3. **Интеграция** — коробка → при `no clear corridor`/сомнении → соты; вставка пути в
   `m_DriveRoute`.

## Открытые мини-вопросы (решаем по ходу/на живом сервере)

- Точная высота вертикального райкаста (не выше среднего авто) и нужны ли косые лучи.
- Адаптивная длина: «10 зелёных рядов на дороге» vs «райкаст 50 м» — что надёжнее.
- Величина `DM_DRIVE_NOSE_OFFSET` (пол-длины ~2 м) — подобрать под машину.
