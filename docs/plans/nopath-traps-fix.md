# План: фикс ground-level nopath-ловушек

Ветка: новая от `master` (после merge `feat/motion-trouble`).

## Цель

Боты в settlement застревают в «ловушках» на уровне земли и в итоге гибнут
(голод/жажда или мили), стоя по 10–40 мин. Устранить класс: «навмеш говорит
проходимо, физика блокирует».

## Диагноз (что уже выяснено)

Два ground-level механизма (НЕ «висит на навмеше» как вышка/крыша — там `bot Y >> террейн Y`; здесь `bot Y ≈ террейн Y`):

1. **Физический клин** — бот зажат капсулой коллизии (угол ворот/стены); навмеш-путь
   ЕСТЬ, но сдвинуться нельзя → `застрял` → `nopath`.
2. **Навмеш-остров на земле** — пешеходный навмеш отрезан (дорогой/платформой/будками),
   локальный ход есть (~13 м), наружу A* пути нет → `nopath`.

Плюс частный подвид «прижат открытой дверью» (см. приоритет 1).

## Приоритет 1 — «прижат открытой дверью» (3732, 7631)

**Механизм (подтверждён ресёрчем `docs/research/door-press.md`)**: бот `TryOpenDoorOnPath` →
`dmBotIntent_OpenDoor` → `OpenDoor`. Фаза-0 «отход назад» ограничена
`DM_DOOR_STEP_BACK_TIMEOUT = 0.1 с` при скорости 2.0 м/с → реальное смещение ≈ 0.2 м,
поэтому `DM_DOOR_STEP_BACK_DIST = 0.5` **никогда не достигается** (таймаут срабатывает раньше).
Для гейт-ворот (`Land_Gate_Small_Blue`, длинная створка, большая дуга) 0.2 м мало — створка
заметает бота.

**Фикс (слоями, по Expansion `eAIBase.HandleBuildingDoors`, eAIBase.c:11497-11742)**:
1. Починить отход: поднять `DM_DOOR_STEP_BACK_TIMEOUT` (~0.55 с) и `DM_DOOR_STEP_BACK_DIST`
   (0.5 → 1.5–2.0 м).
2. Halt перед `OpenDoor` + ждать `IsDoorOpened` (частично уже есть).
3. Адаптивная пауза по `animPeriod` двери (из `CfgVehicles <type> Doors <name> animPeriod`)
   вместо фикс. `DM_DOOR_OPEN_TIMEOUT` (вторым атомом).
4. Проверять фактическое смещение отхода; если заблокирован — фолбэк ±90° страйф через
   `CheckFreeSpace(Aside/-Aside)`.
5. Страховка: детект «толкает створка» (`GetVelocity`≠0 без ввода) → escape в свободную сторону.

**Тест**: `tools/e2e/nopath-wedge-entry.json` (+ новый под 3732). Репро: nomad-бот сквозь
ворота → открывает дверь → застревает. PASS: не застревает. Регрессия: обычная дверь — ок.

**`[нужно проверить]` (гипотезы)**: реальный `animPeriod`/дуга `Land_Gate_Small_Blue` vs
`Land_House_*`; есть ли ≥1 м свободного места позади бота в момент открытия (отделяет «мал
отход» от «угол/стена»); возвращает ли `ConfigGetFloat(... animPeriod)` ненулевое для гейтов;
`Land_Gate_Small_Blue` — нативный `Building`-дверь (не basebuilding `Fence`).

## Приоритет 2 — двойной заборчик 3243

**Механизм**: треугольник из невысокого двойного забора — боту надо **выпрыгнуть**, но
`TryVaultClimb` после фикса C режет высоту `≥ DM_CLIMB_MAX_HEIGHT (2.0 м)`.

**Сначала выяснить** (проб): реальная высота забора. Если `< 2.0 м` — почему не прыгает
(баг vault?); если `≥ 2.0 м` — следствие фикса C, нужен отдельный подход (прыжок-вниз с
невысокого забора не должен блокироваться порогом climb-ВВЕРХ).

**Тест**: `tools/e2e/nopath-island-entry.json` (или новый под заборчик).

## Приоритет 3 — телепорт-спасение (общий «финт»)

**Условие**: если в радиусе **150 м нет реального игрока** И бот застрял (существующий
детект `застрял`/`nopath`-осцилляция) → **телепорт вперёд на 2 м**, с проверкой «оттуда
строится путь по навмешу» (иначе не телепортируем).

**Задел**: детект реального игрока — `dmEntityRegistry.GetPlayers()` + фильтр
`dmAISurvivorBase.Cast(p) == null` (задокументировано в `docs/decisions.md`).

**Тест**: спавн бота в клин/остров, без игрока рядом → бот сам телепортируется и продолжает.
Регрессия: при реальном игроке в 150 м — телепорта НЕТ (не дёргаем на глазах у игрока).

## Готчи (накопленный опыт — перечитывать при работе)

1. **`SurfaceY` — только террейн.** `GetGame().SurfaceY(x,z)` игнорирует крыши/настилы;
   для поверхности — `SurfaceRoadY` или `SampleNavmeshPosition`. (Это был корень бага
   fall-safety на крыше.)
2. **Raycast `sorted` инвертирует порядок хитов.** `sorted=false` → ближайший первым,
   `sorted=true` → дальний первым. `FindLadderBuildingAt` опирается на `hits[0]` при
   `sorted=false` — НЕ добавлять `sorted=true`.
3. **Лестничный `_con` = N вершин** (по одной на ярус), а не 2. Кэш хранит все +
   выбор ближайшей к уровню бота.
4. **`TryVaultClimb` ограничен** `DM_CLIMB_MAX_HEIGHT=2.0 м` (фикс C) — climb вверх.
5. **e2e-мост**: `botdump` видит только named-ботов (не settlement); `clearall` убивает
   ВСЕХ (в т.ч. settlement); пробы `navmeshsample` НЕТ (gap).
6. **Трассировка вейпоинтов** — по `[FSM] MoveTo: subGoal=…` (домен `DM_BOT_DEBUG_FSM`);
   `[PATH] Иду к точке` требует `DM_BOT_DEBUG_PATHFINDER` (в функц. билде выключен).
7. **Клин ловится только nomad-ретаргетом**, а не голым `moveto` (голый проходит насквозь).
   Сценарии — с `Preset: nomad` (тот же пресет, что у settlement).
8. **Restore-очередь спавн-менеджера обходит `MaxBots`** (`RestoreNext()` до проверки капа).
   Перед длинным тестом чистить `$profile:dmBotorama/settlement/*.bin`.
9. **`SnapToGroundExactly` недетерминирован** на висячем навмеш-деке (то террейн, то дек).
10. **Наблюдатель** требует `~/gamer.sh` (настройки страниц памяти) + свежий wine-префикс.
11. **fall-safety стал «инертен» к вертикальным обрывам** (навмеш-сэмпл на краю возвращает
    ту же кромку) — см. techdebt Q; в длинных прогонах следить за смертью «упал с высоты».
12. **Детект смерти «упал с высоты»** — в `.ADM` (always-on): `[bot:dead] … умер: упал с высоты`
    (`m_LastDamageAmmo` содержит `FallDamage`).
