# LOD / масштабирование ботов (план)

> Черновик-план. Цель — поднять число одновременно живущих ботов с ~30 (прод) к масштабу
> Expansion (~180) без деградации серверного FPS. Кандидат на объединение с планами по
> переделке кочевничества/спавна (`ai-development-plan.md` Группа 7, `nomad-exploration.md`,
> `world-poi-spawn.md`) — см. «Связь с планами» ниже.

## Исходные данные (измерено, v3.504)

- 40 settlement-ботов: FPS ~3000 (idle ~5500), мозг ~21 с/окно, райкасты ~5.5/фрейм.
- A/B «мозг есть/нет»: при выключенном мозге пешки всё равно держат ~1.5–1.7 ядра из ~2.0
  — то есть **ванильная симуляция пешки** (физика/скелет/анимация/коллизия) доминирует над
  скрипт-мозгом. Значит, чтобы расти числом, надо экономить не только скрипт, но и
  **стоимость существования/движения пешки**.
- Класс сущности — НЕ рычаг (Expansion тот же `PlayerBase`), разница в тиках.

## Механизмы Expansion (что взять) — `docs/research/expansion-ai-perf.md`

1. **Time-sliced scheduler** (20 ИИ/слайс, бюджет 30%/5 мс, FPS-адаптив). У нас уже есть аналог
   (round-robin слайсинг по числу ботов); расширить до **бюджета по времени** + FPS-адаптив.
2. **LOD ×5 по дистанции до игрока** (`PlayersWithinVisibilityDistanceLimit` пуст → интервал ×5).
3. **Dormant + `DisableSimulation(true)`** (`eAIState_Dormant`) — идл-бот без игроков рядом
   глушит симуляцию.
4. **Дроссель pathfinding/LOS/скана** (рекалк пути ≥2 с + cost-пауза, LOS-кэш с FOV-гейтом,
   бокс-скан 0.1–0.2 Гц) — частично уже есть.

## Направления (по убыванию импакта)

### A. Дальние боты: предрасчёт вместо симуляции движения (главное)

Боты дальше порога от любого игрока (и без зомби рядом — «симулировать не для кого»):
- **Телепорт вместо бега**: НЕ гонять `MoveTo`/физику движения — предрасчитать маршрут и
  «переместить» бота к вейпоинту через N секунд (снап на навмеш, обновление позиции без
  полной симуляции шагов).
- **Стрельба без полной симуляции**: для ботов вне зоны наблюдения — упрощённый расчёт боя.
- **Снизить частоту тика мозга** (LOD ×5).

Бьёт и по скрипту, и по ванильной физике движения — это два главных источника нагрузки.

### B. Dormant / `DisableSimulation`

Идл-ботам вне зоны игрока — `DisableSimulation(true)` (по образцу `eAIState_Dormant`).
**Нужен research-эмпирика**: что именно глушится для AI-пешки (анимация? скелет? физика?),
и достижим ли этот режим для settlement-ботов (строгие guard'ы: нет вейпоинтов, нет leader,
не ROAMING).

### C. Дроссель vision/LOS/скана по дистанции

Дальние объекты райкастить в N раз реже ближних (телеметрия `dmPerfTelemetry` уже даёт
mean/max/p95 — база для «до/после»).

### D. Time-budget слайсинг (расширение round-robin)

Заменить счётчик «ботов/тик» (`DM_BOT_TICK_SLICE`) на бюджет по ВРЕМЕНИ (мс/тик) +
FPS-адаптив (при низком FPS — резать бюджет).

## Связь с планами на переделку

- **Кочевничество/спавн** (`ai-development-plan.md` Группа 7, `world-poi-spawn.md`,
  `nomad-exploration.md`): направление A (телепорт вместо бега) и B (dormant) касаются того,
  как бот перемещается между POI и что делает вне зоны игрока — вероятно сольётся с переделкой
  «поселение исчерпано → следующее» / динамических wrecks.
- **Спавн-менеджер** (`dmBotSpawnManager`): LOD предполагает спавн/деспавн динамических
  патрулей по радиусу от игрока (Expansion `eAIDynamicPatrol`) — доработка `spawn.json`-квоты.

## Порядок работ (предложение)

1. Research-эмпирика `DisableSimulation` для AI (гипотеза «глушит физику/анимацию») — `dayz-research`.
2. Порог «дальний бот» + LOD-интервал (настраиваемо, e2e-ручка) — направление A/D.
3. Телепорт вместо бега для дальних ботов (предрасчёт маршрута) — направление A.
4. Дроссель vision/LOS по дистанции — направление C.

Замер на каждом шаге — `logAverageFps` (отношение 0/N-бот) + `perfstats` + субспаны (методика
в `docs/perf-profiling.md`).
