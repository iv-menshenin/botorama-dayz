# Proposal: лут и исследование (упрощённый дизайн)

> Уточняет и упрощает сырые заметки `docs/looting-and-exploration.md`.
> Статус: proposal — код не писан. Research-детали сигнатур — в `docs/research/loot.md`.

## Мотивация

Боты собирают полезное и выбрасывают ненужное: перцепция предметов → оценка полезности →
взять/выбросить. Плюс (опционально) исследовать незнакомые места. Задачи T13–T16 плана.

## Ключевое решение — разнести 3 несвязанных слоя

Сырой вариант смешивает три вещи в одной конструкции. Их надо разнести:

1. **Классификация** — «что это за вещь» (категория). Статично, дёшево.
2. **Полезность** — «нужна ли мне эта вещь сейчас» (оценка 0..1). Динамично.
3. **Поведение** — «пойти, взять, выбросить» (интенты/состояния).

Исследование строений — **отдельный опциональный слой**, не связанный с лутом.

## Слой 1 — Классификация

Один mapper:

```
dmLootCategory dmLoot.GetCategory(ItemBase item)
```

на базе ванильного класс-наследования (как Expansion `eAIItemTargetInformation`):
`IsInherited(Edible_Base)`, `IsWeapon()`, `IsMagazine()`, `IsAmmoPile()`, `IsClothing()`,
`IsInherited(WeaponCleaningKit)`, `IsInherited(SewingKit)`, `IsInherited(BandageDressing)`
и т.д. Категории:

- `FOOD` (Edible_Base)
- `WEAPON` / `MAGAZINE` / `AMMO`
- `CLOTHING` (по слотам, как Expansion `eAILootingBehavior`)
- `REPAIR` (чистка оружия / швейный / скотч)
- `MEDICAL` (бинты)
- `OTHER`

Здесь НЕТ списков желаний — только категория.

## Слой 2 — Полезность

Вместо трёх классов (`Wishlist` + `Requirements` + `CalcDesired`) — ОДИН scorer:

```
float dmLoot.CalcUtility(dmAISurvivor bot, ItemBase item)   // 0..1
```

Принцип — как Expansion `CalculateThreat` (ценность `q / distance` + фильтры), но с
динамическими нуждами:

- **базовая ценность** `q` по категории (оружие > магазин > патроны > еда/ремонт/медицина);
- **нужда-модификаторы**: голоден → еда выше; нет оружия → оружие выше; есть повреждённое
  → ремкомплект выше; ранен → бинт критично;
- **фильтры-исключения** (→ 0): нет патронов под ствол; уже есть N таких; испорчено/разрушено;
  недостижимо;
- **дистанция**: ближе → выше.

«Желание»/«отвращение» (`SetDesired`/`SetJunk`/`Ignore`) схлопываются в простой **чёрный
список** недавно выброшенных вещей (таймаут 5 мин) — чтобы не подбирать снова. Несколько
списков-желаний не нужны — нужды и так выражены модификаторами.

## Слой 3 — Поведение

- **`dmBotIntent_PickUp`** (EXCLUSIVE): путь к предмету → `TakeEntityToInventory` → Finish.
  Гейты: нет места / вещь занята игроком / недостижимо.
- **`dmBotState_Looting`**: перцепция предметов в радиусе (предмет = обычная цель, тот же
  perception/LOS) → выбрать max `CalcUtility` → PickUp. При переполнении — выбросить вещь
  с наименьшей полезностью.

## (Опционально) Исследование

Сырой `Explorer` (флаг посещения здания, список лута на здание, «маршрут по комнатам») —
**переусложнён**. Упростить до одного из двух:

- **(а) итем-драйвен** — вообще без «зданий»: просто видим предметы рядом (это и есть
  поведение Expansion);
- **(б) лёгкий блуждающий слой** — помнить недавно посещённые позиции, идти в незнакомые
  (без комнат и без списков лута).

Вариант (а) даёт 90% пользы за 10% кода. «Маршрут по комнатам» — отдельная фича, если
вообще понадобится.

## Критическая оценка — что переделать

| Сырое предложение | Оценка | Решение |
|---|---|---|
| Классификация 5 категорий | ок, но хардкод | mapper на ванильном наследовании |
| `Wishlist` (SetDesired/SetJunk/Ignore) | частично избыточно | чёрный список + scorer |
| `Requirements` (тик 5с, индексы с делением, discard, repair, damaged, ruined) | **переусложнён** | одна `CalcUtility` + простой drop |
| `CalcDesired` fallback «то определим» | **не дописано** | явный default в scorer |
| `Explorer` (здания, списки, радиусы 50/200/500/75/100) | **переусложнён** | отдельно / упростить |
| `LookAround` «маршрут по комнатам» | **переусложнён** | просто идти к предмету |

## Гибкость и поддерживаемость

- **Гибко**: динамические нужды (голод/ремонт/оружие) поверх `q/distance` — легко добавлять
  новые нужды модификаторами, не трогая классификацию и поведение.
- **Поддерживаемо**: 2 слоя (mapper + scorer) вместо 3 склеенных классов; нет списков
  «здание → лут → флаги посещения».
- **Слабое место сырого варианта**: `Requirements.Update` раз в 5с тянет за собой 5
  обязанностей (инвентарь, индексы, discard, repair, damaged) — при любой правке одной
  ломаются другие. Разнесение решает это.

## Сравнение с аналогом (Expansion)

| | Expansion | Наш proposal |
|---|---|---|
| Перцепция предмета | предмет = цель, тот же LOS | то же |
| Полезность | `CalculateThreat` = `q/distance` + фильтры | `CalcUtility` = `q/distance` + **нужды** |
| Категории | `eAILootingBehavior` (статичный bitmask) | `GetCategory` (ванильное наследование) |
| Динамические нужды | нет (статичный конфиг) | **есть** (голод/ремонт/оружие) |
| Исследование строений | нет (итем-драйвен + патруль) | опционально, упрощённо |

Наше главное преимущество над Expansion — динамические нужды. Главная экономия против
сырого варианта — не делать `Explorer` и «маршрут по комнатам».

## Фазы реализации (порядок)

1. **Классификация** — `dmLoot.GetCategory` (+ тест-команда `/bot loot class {item}`).
2. **Scorer** — `dmLoot.CalcUtility` + чёрный список выброшенного (+ команда вывода утилиты).
3. **PickUp + Looting + drop** — перцепция, взять, выбросить при переполнении.
4. **(Опционально) исследование** — вариант (а) или (б), отдельно.
