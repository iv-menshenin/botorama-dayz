# Поиск вещей

Нам нужно классифицировать вещи:
1. Еда/Вода
2. Оружие/Патроны
3. Одежда/Обувь
4. Инструменты для ремонта
5. Прочее


Далее желанием бота "владеть" вещью определяется двумя механиками:
- Потребностями
- Списком желаемого

## Класс "список желаемого"
работает как регистр в котором 
class Wishlist:

    ### SetDesired устанавливает уровень потребности бота в каком то классе вещей
    SetDesired(itemClass, necessity)
        itemClass - может быть базовым, чтобы рабоатть через Inherit
        necessity - уровень потребности от 0 до 1, например если бот умирает от голода, то потребность в Edible_Base будет 1
    ### Удаление
    RemoveDesired(itemClass)

    ### SetJunk устанавливает уровень "отвращения" к какому то классу вещей - бот не будет их трогать
    SetJunk(itemClass)

    ### Ignore заставляет игнорировать вещь. Например, если кончились патроны на пистолет, бот его выбросит и будет игнорировать, чтобы не поднять обратно
    Ignore(EntityAI item)
    Unignore(EntityAI item)

    ### CalcDesired определение "желания" предмета - возвращает уровень от 0 до 1
    float CalcDesired(EntityAI item)
        проверяет сначала по листу исключений, если исключено, то вернет 0
        потом проверяет по листу Junk - если есть - возвращает 0
        потом ищет по Desired и возвращает найденное значение
        если нигде не найдено - то определим:

## Класс "потребности"
работает как "живой" анализатор вещей, которые есть у бота и которых нет
class Requirements

    ### Update тикает один раз в 5 секунд
    Update()
        определяет список вещей, которые есть у бота в инвентаре и проставляет каждой индекс необходимости
        если у бота есть еда, то первый Item еды получает 1, второй 0.5, третий 0.25 - далее по убывающей
        т.е. каждый item, класса, который уже есть в инвентаре, получает индекс в два раза ниже, чем предыдущий, потому что дублирует
        В этой разметке первая вещь в инвентаре получает индекс в зависимости от классификации:
            Еда/Вода = 1
            Оружие/Патроны:
                Оружие = 1
                патроны подходящие по калибру - всегда 1 (индекс не деградирует)
            Одежда/Обувь = 0.5
            Инструменты для ремонта = 1
            Прочее = 0.5

        Каждая вещь в инвентаре записывается в кэш:
            1. Оружие
            2. Одежда/Обувь (только та, что надета)
            3. Инструменты для ремонта (швейный набор, для починки оружи, скотч и т.д.)

        Если в инвентаре мало свободного места (меньше 75%), то начинается режим "выбрасывания":
            бот "хочет" избавиться от вещей, которые занимают место:
            все вещи сортируются в порядке обратности индекса и выбрасываются до тех пор,
            пока место не будет освобождено. каждая выброшенная вещь записывается в вишлист, как Ignore
            этот класс должен хранить список выброшенных вещей с меткой времени - через 5 минут такие вещи должны "чиститься" - Unignore

        Затем идет проверка состояния вещей:
            Оружия:
                если есть поврежденное оружие, то проверяется есть ли починка для оружия. если нет: добавляет в вишлист починку для оружия
                если поврежденного оружия нет - починка для оружия удаляется из вишлиста
            Одежда:
                если есть поврежденная одежда, проверяется есть ли инструменты для ремонта одежды, если нет: добавляются в вишлист
                если нет поврежденной одежды - из вишлиста удаляются инструменты для ремонта одежды (швейный набор и скотч)
            Обувь:
                если есть поврежденная обувь, проверяется есть ли инструменты скорняка, если нет: добавляются в вишлист
                если нет поврежденной обуви - из вишлиста удаляются инструменты скорняка

        Поврежденные предметы записываются в отдельный список поврежденных предметов:
            array<EntityAI> DamagedItems

        Инструменты для починки записываются:
            array<EntityAI> RepairingTools

        Разрушенные предметы (Ruined) - выбрасываются, это делается прямо тут.

        Если нет оружия, нужно добавить Weapon_Base в вишлист
        Если нет ножа, нужно добавить нож в вишлист

    ### RequireToRepair дает Pair - поврежденная вещь и инструмент для починки. Если инструмента нет - така вещь не выдается
    RequireToRepair()
        Проверяет, что нужно чиить по списку DamagedItems и ищет в инвентаре инструмент для починки
        Если есть, то выдает Pair<Вещь, Инструмент>

## Класс "исследователь"
class Explorer:
    Хранит список домов (строений), которые бот посещал
    Нужен "период забывания" - после которого бот забывает здание
    Фильтр: здания берем только те, где есть лут

    # OnUpdate - выполнять раз в минуту
    OnUpdate():
        сканировать сущности в радиусе 50 метров от бота
        запоминать здания - помечать их как "непосещенные", если обнаружено новое здание
        запоминать все EntityAI и привязывать их к ближайшему зданию
        т.е. у нас будет список из зданий с стрибутами:
            флаг посещения
            список лута к этому зданию, каждый предмет имеет флаг "проверено"

        если здание дальше чем 500 метров до бота - забыть его
        если здание дальше чем 200 метров до бота и оно не было посещено - забыть его

    # получить очередь исследования
    GetNearest(float radius)
        дает ближайшее непосещенное здание в радиусе radius от бота

## Поднять вещь
PickUp - это интент, который
    строит маршрут до предмета, а когда бот достиг этого предмета, заставляет его подобрать этот предмета:
        проигрывается анимация подбирания
        предмет перемещается в инвентарь бота

    Блокировка входа: нет места в инвентаре

## Исследовать здание
LookAround - интент проверки здания
    получает ближайшее непосещенное здание к боту, но не дальше 75 метров от бота.
    строит маршрут внутрь здания. если можно определить в здании комнаты (помещения), то построить маршрут по всем комнатам
    в процессе выполнения маршрута, если до любого из предметов здания расстояние меньше 3 метров:
        проверять "нужность" предмета по wishlist, если нет требований, то проверять по классификации:
        1. Еда/Вода - взять
        2. Оружие/Патроны - взять, если нет оружия, патроны взять подходящие по калибру
        3. Одежда/Обувь - сравнить с тем, что надето:
            если Cargo по размеру меньше, чем на 4 слота, игнорировать
            если Cargo больше, взять и перекинуть все вещи из одного Cargo в другое
            если Cargo такое же по размеру, выбрать вещь исходя из:
                Большая остаточная ХП - GetHealth01
                Большее утепление - если разница в Health меньше 25%

        4. Инструменты для ремонта - взять (если нет такой же вещи в инвентаре)
        5. Прочее - не брать

## Новые состояния:

Exploration
    Вход: если в радиусе 100 есть непосещенное здание Explorer.GetNearest(100)

    Выполнение:
        Управлет интентами LookAround и PickUp (постоянно их держит включенными)
        Получает ближайшее здание в радиусе 200м:
            Добавляет его в LookAround
            Если любой предмет из этого здания ближе к боту, чем 3 метра, добавляет предмет в PickUp (эксклюзивный)
            
        Если нет подходящего предмета - PickUp не удаляется, просто ставится m_Active = false

    Выход: если в радиусе 200м нет непосещенных зданий - удаляются интенты
