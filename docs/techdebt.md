## D. Архитектурный долг

- **средний** — `LoadFSM(presetName)` не реализован — в плане был метод загрузки пресета
  по имени; в коде есть только `SetFSM` + билдер `/fsm`. Пресеты по имени не грузятся
  (связано с A: `Presets/` мёртв).
- **средний** — `Despawn` не чистит ссылки (`dmAISurvivor.Despawn`) — удаляет пешку, но
  не сбрасывает `m_FSM`, пулы интентов, `m_Targets`. Ref-циклы/утечки (в `codeguide.md`
  уже отмечено «чистить явно» — не сделано).
- **низкий** — пер-канальный арбитраж («CRITICAL+PARALLEL переопределяет движение
  CRITICAL+EXCLUSIVE») — отложен; сейчас exclusive глушит всё безусловно.
- **сделано** — **кастомный movement-command** (правильный доворот на ходу). Все три фазы
  закрыты (`7596ade`, `309fd3b`, `5043847`): `HeadingModel` override → консолидация применения
  в пешке → рамп скорости + доворот-с-притормаживанием + политика комфорта корпуса.
- **низкий (отложено до Fight)** — **непрерывная «наименьшая дискомфортность»**: текущая
  политика `ComputeBodyYaw` дискретна (`FULL`/`AUTO`/движение). Непрерывный компромисс
  (`w_head·|headAngle| + w_move·|moveAngle|`) нужен, когда появится одновременное «двигаться
  к укрытию + смотреть на врага» (Fight/стелс). Каркас (`m_MoveYaw` + `ComputeBodyYaw`) уже есть.

## F. Движение / качество ходьбы (замечания из тестов)

- **средний** — `MoveTo`: ступни «проскальзывают» вправо при ходьбе, бот идёт чуть
  правым плечом, а не ровно. Похоже на артефакт движения относительно корпуса
  (`OverrideMovementAngle`) + слайд-поворота — надо выровнять.
- **средний** — пауза между точками патруля: `MoveTo` завершается сразу (паузы в нём
  нет), задержку даёт `Patrol` (`DM_PATROL_DWELL_TIME = 5.0`). Хотим, чтобы патруль
  шёл без задержек → убрать/сократить dwell (решить, оставлять ли короткую остановку).
- **низкий (далёкое будущее)** — расширение recovery: когда научим персонажа
  пригибаться — при зависании пробовать пригнуться; потом прыгать; и только перепробовав
  всё (бок/пригибание/прыжок) — считать зависшим и `Fail()`.
- **средний** — Мили: бот иногда стоит в неудобной позиции и не выравнивается под бой
  (доворот/позиционирование при подходе).
- **средний** — Мили: звук/искры удара «по твёрдому» — `hitZoneIdx = -1` (нет component
  index без райкаста); фикс — получить index через коллизию/melee-targeting или кастомный звук.
- **низкий** — Двери: hand-анимация открывания добавлена (`dmBotIntent_OpenDoor` →
  `AddCommandModifier_Action(CMD_ACTIONMOD_OPENDOORFW)`, research в `navigation.md`).
  Проверить визуально, что жест реально играется (граф уже содержит `OpenDoorErc/Cro`);
  при предмете в руках возможен ре-синк рук → `RequestHandAnimationStateRefresh()`.
  Гейт против full-body команд и таймаут+`DeleteCommandModifier_Action` — уже в коде.

## G. Интенты: жизненный цикл (гигиена пула)

- **автодедлайн (сделано, `2.9`)**: интент без дедлайна (`m_Deadline < 0`), проживший в
  пуле дольше `DM_INTENT_MAX_AGE` (5 мин), удаляется арбитражем. Ни один интент не живёт
  вечно.
- **правило для State**: состояние обязано следить, что его интенты ещё действуют, и
  **пересоздавать** их, если их перезатёрли/удалили (например автодедлайном). Сейчас
  `Stealth` держит stance-интент с `deadline = -1` — после 5 мин он умрёт, и состояние
  должно его пересоздать (пока не реализовано).
- `/bot intent`-приказы (командный пул) получили дедлайн 1 мин (`goto`, `stance`), чтобы
  не копиться; `crouch` — 5 мин, `lookAt`/`lookAtMe` — 30 с.

## H. Прицеливание (огнестрел, dmAiming)

- **сделано** — **Отдача на выстрел** (recoil): `dmBot_Fire` → `AddRecoil(DM_AIM_RECOIL_MODIFIER)`,
  `dmAiming.Update` гасит `m_RecoilPitch` и прибавляет к питчу (обе ветки). Осталось:
  реальная формула `recoilModifier` от веса/патрона.
- **средний** — **Strafe-factor пропущен**: `eAIAimingProfile` штрафует точность за
  «хаотичный стрейф» цели через `DayZPlayerImplement.GetStrafeFactor()` — это кастомный
  метод из dayz-devaliada, в ванили его нет. В `dmAiming` блок strafe НЕ перенесён
  (`strafeFactor = 0`). Ввести свой аналог или отказаться.
- **средний** — **Видимость — заглушка 100%**: `eAI_GetVisibility` в `dmAiming` заменена
  константой `1.0` (ночь/туман/дым не снижают точность). Ввести свою модель видимости.
- **низкий** — **Выстрел через round-trip**: `dmBot_Fire` берёт направление из
  `GetWeaponAimDirection()` (пересборка из `m_AimRelAngleLR/UD`), а `dmBotIntent_Aim` пишет
  эти углы из `m_Aiming.GetAimDirection()` через `SetAimDirection`. Между «выставил углы» и
  «выстрелил» корпус может довернуться (`ApplyBodyTurn` в CommandHandler), давая малую
  ошибку. Чище — стрелять сразу мировым `m_Aiming.GetAimDirection()` (минуя round-trip);
  визуальный ствол оставить на сглаженных углах.
- **низкий** — **Самопроверка разброса**: `/test bot aim` теперь гоняет новый путь
  (Shooting + `dmBotIntent_Aim` + `dmAiming` + перезарядка), но явной самопроверки
  разброса (выстрелы-до-убийства как PASS/FAIL) нет — сейчас это наблюдение.

## 2. Реакции мозга на состояние тела (следующая фаза)

Сейчас мозг честно не двигает бессознательное/мёртвое тело, но не «реагирует»
осознанно. Отложено:

- Холод → искать тепло (костёр/укрытие/одежду).
- Голод/жажда → искать еду/воду (вместе с симуляцией голода/жажды — статы уже
  тикают, но мозг не ест/не пьёт).
- Мало стамины → отдых/шаг.
- Боль/урон/бой → драка или бегство.
- **Мили-бой (ближний бой)**: сейчас мили-логика отключена (`dmBotMeleeFightLogic_LightHeavy`
  пропускает `HandleFightLogic`, чтобы не падал VM Exception на null-`hcm`). В будущем
  проработать боевой FSM/интенты + кастомную мили-логику (по образцу Expansion
  `eAIMeleeFightLogic_LightHeavy`), тогда и убрать заглушку.
- Ослепление/токсичность/утопление → сенсорика и реакции.
- Болезни (простуда/грипп/пневмония от холода) — модификаторы есть, но нет ни
  реакции, ни тестов.
- **Разбудить бессознательного бота**: у обычного игрока есть меню «привести в чувство»
  (действие по бессознательному телу), а для бота это не работает — ванильное действие
  рассчитано на игроков. Разобраться позже (кастомное действие/взаимодействие с ботом).
- **Связывание бота**: меню связывания есть, но при начале связывания анимация
  прерывается. Ванильное restrain-действие рассчитано на игроков; для бота нужно
  разобраться (кастомное действие/обработка анимации) позже.

## 3. Проверочные риски честной симуляции (следить при прогонах)

- Анимация головы при гейте `ApplyLookVars` в нокауте (не дёргается ли граф).
- Foot-step turn при сбросе (`dmAI_StopTurn`) — не застревает ли `m_TurnState`.
- Устаревший `m_ActualSpeed`/`m_DesiredSpeed` → рывок после выхода из нокаута.
- Синхронизация взгляда на клиенте при гейте.
- `HeadingModel` в нокауте (читает `GetMovementState`).
- Существующие сценарии (`overload`/`patrol`) — боты теперь реально умирают от
  внешнего урона; тесты могут «глохнуть».
- Спавн в воздухе: кик `MoveTo` на 1 м будит физику (бот падает). Если навмеш не
  найден (спавн сильно над рельефом) — кик не сработает, нужен fallback (снап по
  рейкасту/навмешу в `Spawn`).
