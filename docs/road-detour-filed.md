# Объезд препятствий (road detour) — полевая записка

> Только про объезд препятствий водителем: план, архитектура, что сделано, что осталось,
> какие проблемы встретили. Пишется как хендофф, чтобы не переоткрывать известное заново.
>
> **СТАТУС: ДЕТЕКТ ПРЕПЯТСТВИЙ ЗАКРЫТ (v3.272)**. Сканбокс удалён; детект целиком на тонких
> лучах `ObjIntersectGeom` (гексагональный веер + вертикаль). Бетонные «baked-static»
> ограждения (`Static_rock_monolith`) ловятся. Лут (одежда/бочки) фильтруется. См. §7.

---

## 1. Цель

Бот-водитель едет по дорожному графу и должен **объезжать препятствия** на дороге:
бетонные ограждения, остовы машин, контейнеры и т.п. На тестовом участке это
**комплексное поле препятствий на ~100 м** (несколько ограждений + остовы + контейнер
подряд). Задумка: сначала **коробка** (узкий одиночный манёвр), если не влезает —
**соты** (грид, обойти весь комплекс по найденной траектории).

Ключевое требование заказчика (дословно):
> сначала прямоугольник (бокс), потом соты — **всё это время бот должен снижать скорость
> вплоть до остановки**; только если **и прямоугольник и соты дадут FAIL**, бот сдаётся
> и выходит — но **скорость машины должна быть равна нулю**. Если препятствие есть, а
> маршрута ещё нет — бот должен **тормозить**.

## 2. Архитектура (два уровня)

Всё живёт в `src/core/4_World/Entities/Bot/Intent/dmBotIntent_Drive.c` (интент вождения)
и `src/roads/4_World/Pathfinding/dmRoadHoneycomb.c` (соты).

### Поток (интент вождения, `TickDriving`)

1. **`TickDetect`** — вперёд-райкаст на высоте корпуса (`RaycastHits`, `ObjIntersectGeom`,
   `CollisionFlags.ALLOBJECTS`) детектит препятствие. Фильтр: свой кузов/водитель
   (`pIgnore=m_Car` + `hit.obj/parent == m_Car || driver`), земля (`obj==null && dir[1]>EPS`
   — нормаль вверх), кусты (`IsBush`). Ставит `m_DetourActive` + `m_DetourBrakeTimer`.
2. **`PerformDetour`** — бокс: пробует 7 полос (`RaycastHits` по полосам), если есть
   чистый коридор нужной ширины — вставляет коробку `boxA..boxE`. Если коридора нет
   (`no clear corridor`) — переходит в **соты** (`m_HoneyState = 1`).
3. **`TickHoneycomb`** — соты считаются асинхронно; на это время бот **жёстко тормозит
   до нуля** (нейтраль + `DM_DRIVE_HARD_BRAKE=1.0`, `m_SpeedLimit=0`). По `DONE` →
   `InsertHoneycombPath`, по `FAILED`/вырожденному пути → `Fail` **только при скорости
   ≤ `DM_DRIVE_EXIT_MAX_SPEED` (2 км/ч)**.
4. **`InsertHoneycombPath`** — срезает хвост маршрута с текущего индекса, вставляет путь
   сот, **ре-снэпает роутер** `dmRoadRouter.Setup(дальняя_точка_сот, m_TargetPos)` (иначе
   роутер исчерпан ещё на первом рефилле и интент финиширует на хвосте обходного пути).

### Соты (`dmRoadHoneycomb`)

- **Территория**: сетка `m_RowCount × m_Width`; длина — дефолт 110 рядов (~82 м при 0.5 м
  гекса), полуширина вычисляется в `Start()` из измеренной ширины дороги
  (`dmRoadProbe.RoadWidth`): `m_HalfWidth = RoundF(roadWidth / across-шаг)` → сетка = 2×
  дорога (константы `DM_GRID_ROAD_HALF_WIDTH`/`DM_GRID_SHOULDER_HALF_WIDTH` удалены).
  Для диагностики (`griddump`) ширина настраивается параметром `Start(..., widthCells)`;
  `widthCells = 0` означает «измерь дорогу».
- **Origin** — НЕ центр машины, а **бампер + радиус капсулы**:
  `carPos + carDir * DM_DRIVE_HONEY_ORIGIN_OFFSET (3.5 = нос 2.0 + радиус капсулы 1.5)`,
  вдоль реального курса машины (`carDir`). Кузов остаётся позади территории.
- **Пайплайн** (`Tick`): `STATE_COLORING` (`ColorRow`/`ColorCell` по `DM_GRID_ROWS_PER_TICK=3`
  ряда за тик) → `STATE_MARK_SAFE` (`MarkSafe`) → (синхронно) `BuildGraphRoute`
  (`FindGoalWaypoint` → слоёный граф SAFE-середин → DP-кратчайший путь).
- **Детект клеток** — ДВА источника:
  1. **`ScanEntities()`** (разовый проход в `Start()`, основной, «хак») — сканбокс территории
     (`SceneGetEntitiesInBox`, статика + динамика) → у каждой сущности bbox
     (`ClippingInfo` + `ModelToWorld`) → клетки, пересекающие bbox, → `CELL_RED`.
     Фильтр лута: `ItemBase.Cast(obj) && !IsCarBodyPart(type)` → пропуск (лут не красим).
  2. **`RaycastBlocked()`** (fallback) — вертикальная капсула сверху-вниз; практически не
     даёт хитов (см. §5), оставлен для бетонных «baked-static» блоков.
- **`ColorRow`** не перетирает уже-RED клетки от `ScanEntities` (иначе рейкаст вернул бы GREEN).
- **Адаптивный рост** (`TickColor`): после первого RED (`m_SeenRed`) сетка растёт ещё
  `DM_GRID_CLEAR_ROWS=10` «чистых» рядов и останавливается («дорога снова свободна»).
- **Goal** (`FindGoalWaypoint`): самый глубокий вейпоинт маршрута внутри территории (строка +
  колонка); выход = ближайшая SAFE-клетка к голу, старт = `FindNearestSafe(0,0)`.

## 3. Что сделано (работает)

- **Детект препятствий** — вперёд-райкаст с нормаль-фильтром (земля/куст/свой кузов).
- **Бокс-объезд** — на HescoBox и ВПП подтверждён E2E.
- **Соты** — асинхронный грид: раскраска → mark-safe → слоёный граф → кратчайший путь.
- **Гейт интента убегания за рулём** — `EscapeDanger`/`EvadeAim` заблокированы, пока
  `m_Pawn.IsInVehicle()` (иначе прицел игрока выбивал водителя из кресла).
- **Тормоз до нуля во время сот** — нейтраль + `DM_DRIVE_HARD_BRAKE`.
- **Гейт высадки по скорости** — `Fail` только при `speed ≤ 2 км/ч`.
- **Origin от бампера** — соты не бьют по собственному кузову.
- **Ре-снэп роутера** — маршрут продолжается к цели после обходного пути.
- **Ориентация грида по дороге** — `d = normalize(target − start)`, а не по оси X.
- **Отрисовка сот гексагонами** (визуально) — в `tools/render_honeycomb.py`.
- **ХАК: scanbox + bounding box** — сканбокс территории → bbox каждой scene-сущности →
  пометка клеток RED. Закрывает остовы/седан/контейнер/шатры/кузовные части.
- **Фильтр лута по классу** — `ItemBase` (лут) пропускается, кузовные части (`CivSedan*`/
  `Sedan_02*`/`Hatchback*`) — whitelist (они `ItemBase`, но твёрдые блокеры).

## 4. Проблемы и как решены (хронология)

1. **Водитель «исчезал»/высаживался при прицеле игрока.** Причина: `dmVision` ловил прицел →
   `EvadeAim()` создавал MOVE-интент, конфликт с командой транспорта выбрасывал водителя.
   **Фикс**: гейт `if (m_Pawn && m_Pawn.IsInVehicle()) return;` в `EvadeAim`/`EscapeDanger` (`2ff5c80`).
2. **Мотор «глох» на 43 км/ч** (сперва НЕПРАВИЛЬНО диагностировали как «сцепление/жёсткий
   тормоз» — нейтраль, тормоз 0.5, рестарт двигателя — всё мимо). Реальная причина: после
   вставки пути сот роутер был исчерпан (`refill +0 exhausted`) → условие финиша → `Finish`
   → `StopCar` → высадка на ходу. **Фикс**: ре-снэп роутера + гейт высадки по скорости (`da67066`).
3. **Соты били по собственному кузову** (капсула 1.5 м из центра машины) → первые ряды RED →
   сетка гасилась на ~10 м, не доходя до барьера. `pIgnore`+фильтр `obj/parent` не помог.
   **Фикс**: origin от бампера (`f8193bf`).
4. **Райкаст не детектил препятствия — сага.** Пробовали по очереди: вертикальную капсулу
   (высота), горизонтальный луч (нормаль), 6 диагональных лучей «снопом», разворот сверху-вниз,
   `ObjIntersectView`. Итог: **`ObjIntersectGeom` даёт 0 хитов по baked-static геометрии**
   (остовы/контейнер/шатры/бетон), а `ObjIntersectView` ловит только часть; диагональный сноп
   покрывает лишь узкий коридор высот. Райкаст как детектор сот — тупик.
5. **РЕШЕНО хаком**: детект перенесён на **scanbox + bbox** (`ScanEntities`), райкаст оставлен
   fallback'ом. Scene-объекты (остов/седан/контейнер/шатры/кузов) теперь RED, `path=6`.
6. **Сканбокс хватал и лут** (штаны/маска/банка/патроны/M16/шлем/камень) — сначала пробовали
   фильтр по размеру bbox (`maxDim<1.0`) — **ненадёжен** (`ClippingInfo` завышает bbox лута,
   занижает шатрам). **Фикс**: фильтр по классу `ItemBase` + whitelist кузовных частей.

## 5. Ключевые факты (чтобы не переоткрывать)

- **`ObjIntersectGeom` даёт 0 хитов по baked-static scene-геометрии** (остовы/контейнер/
  шатры/бетон) в сотах; `ObjIntersectView` (визуал) ловит часть (седан/шатры в v3-прогоне).
  Рабочий детект для scene-объектов — **scanbox (`SceneGetEntitiesInBox`)** + bbox.
- **Бетонные ограждения — «baked-static» геометрия карты без scene-объекта**: `scanbox`
  их НЕ видит (0 сущностей), `surfshootout` на 6992,12675 видит `asphalt_ext` (бордюр/террейн).
  Их закрывает НЕ сканбокс, а отдельный механизм (рейкаст/высота террейна) — открытый хвост.
- **`Game.SurfaceY(x,z)` возвращает верх статических объектов** (барьера), а не чистый террейн
  (по ранней гипотезе; позже surfshootout показывал `terrainY=133.406` — проверить при
  возврате к бетону, что именно отдаёт `SurfaceY`).
- **`hit.dir[1]` — НЕ надёжная нормаль поверхности**: при лучах сверху-вниз земля (`obj=null`)
  даёт `dir[1]=0.0`, а не `+1`; фильтр «нормаль вверх» для отсева земли не работает.
- **`ClippingInfo(mm)` даёт ненадёжный bbox**: луту (M16A2) завышенный (~4 м), шатрам
  вырожденный (<1 м). Размером блокеров от лута не отличить.
- **Лут — это `ItemBase`** (одежда/еда/оружие/патроны/шлемы/рюкзаки/камни). Кузовные части
  `CivSedanHood_BlackRust`/`CivSedanDoors_CoDriver_BlackRust` — ТОЖЕ `ItemBase`
  (`CarDoor : ItemBase`), но твёрдые блокеры → whitelist по префиксу типа.
- **Картографические военные шатры `Land_Mil_Tent_*` — НЕ `ItemBase`** (наследуют
  `HouseNoDestruct`), красятся корректно; деплой-палатки `TentBase` — `ItemBase` (лут).
- **Тёплый прогон**: первый griddump после старта сервера может недогрузить baked-статику
  (37 сущностей вместо 41). Греть сцену или повторять прогон.
- **Высота сканбокса** `halfY=3.0` не покрывает объекты в кювете (напр. `Land_Wreck_hb01_aban2_blue`
  на Y≈128.4 при центре коробки Y≈132.8) — пред-существующее ограничение `ScanEntities`.

## 7. Текущее состояние (v3.281, вождение интегрировано)

- Спек по **поведению водителя** выполнен: тормоз до нуля, высадка только при ~2 км/ч,
  гейт убегания, райкасты от бампера, грид по дороге.
- **Детект препятствий закрыт**: тонкие лучи `ObjIntersectGeom` (гексагональный веер +
  вертикаль) ловят scene-объекты и baked-static монолиты; лут/одежда/бочки фильтруются
  (`IsClothing()` + `DeployableContainer_Base`). Сканбокс `ScanEntities` удалён.
- **Pathfinding — слоёный граф + кратчайший путь (v3.279)**: центральная линия удалена.
  Маршрут строится на графе: зелёные клетки = SAFE; по каждому ряду — «зелёные середины»
  (центры SAFE-интервалов); рёбра только вперёд между соседними рядами, валидны если отрезок
  между центрами не пересекает RED (`SegmentCrossesRed`); вес = XZ-длина; DP-кратчайший путь
  от входной SAFE-клетки (`FindNearestSafe(0,0)`) до выхода (`FindNearestSafe(goalCol, goalRow)`).
  Затем путь сжимается string-pulling'ом (дедуп) до точек поворота: одинаковые/коллинеарные
  клетки соседних рядов схлопываются, отрезки пере-валидируются против RED. Клетки финальных
  waypoint'ов дампит `GetWaypointCount`/`GetWaypointCell` → `griddump.json` `WaypointCells`.
- **Не закрыто**: замеры производительности (§6 п.3).
- **Интеграция вождения (v3.281)** — интент `dmBotIntent_Drive` переведён на фазовую машину
  `m_DrivingPhase` (`DPH_STARTING`/`DPH_DRIVING`/`DPH_DETOUR`, детерминированные переходы):
  коробка-объезд удалена (только соты); в `DPH_DETOUR` лучи препятствий выключены; достижение
  waypoint'а — по проекции носа на полилинию маршрута (`m_RouteCumDist` + `ComputeProgress`),
  а не по 3D-координатам. Сетка строится за ~1 с (budget-loop `DM_DRIVE_GRID_BUDGET_MS`),
  адаптивный стоп — 50 м чистого полотна (`DM_GRID_CLEAR_ROWS=67`).
- **ОТКРЫТО (v3.281, уточнено v3.282)**: на тестах бот **перестал садиться в машину** —
  `CrewMember(DRIVER)=null` весь прогон; мотор заводится и ревёт до отсечки (~4955 RPM),
  но колёса не крутятся (`speed≈0`). Диагностика: `StartCommand_Vehicle` даёт `ok=true`,
  `isGettingIn=true`/`inVehicle=true`, но членство в экипаже не устанавливается
  (`crew=false` стабильно); `CrewMember(DRIVER)` кратковременно `==pawn` на get-in, затем
  сбрасывается. E2E-харнесс `drivetest` (v3.282, `tools/e2e/drive-immediate-grid.json`)
  детектит это как `seating timeout`. Требование: блокировать зажигание и движение машины,
  если на водительском сиденье физически нет именно этого бота (см. `docs/techdebt.md` J3).
- **Вождение по-прежнему на паузе** заказчиком (детект был хвостом этой паузы — теперь закрыт).

## 8. Релевантные константы

- `DM_DRIVE_NOSE_OFFSET = 2.0` — опорная точка вождения (нос).
- `DM_DRIVE_HONEY_ORIGIN_OFFSET = 3.5` — вынос origin сот (нос + радиус капсулы).
- `DM_DRIVE_HARD_BRAKE = 1.0` — полный тормоз в нейтрали при сотах.
- `DM_DRIVE_EXIT_MAX_SPEED = 2.0` — порог скорости высадки (км/ч).
- `DM_GRID_MAX_ROWS = 110` — жёсткий кап длины территории (рядов, ~82 м при 0.5 м гекса).
  Полуширина территории вычисляется в `Start()` из измеренной ширины дороги
  `dmRoadProbe.RoadWidth` (флор `DM_ROAD_MIN_WIDTH`): `m_HalfWidth = RoundF(roadWidth /
  (DM_GRID_HEX_SIZE * 0.8660254))` → сетка = 2× дорога. Константы
  `DM_GRID_ROAD_HALF_WIDTH`/`DM_GRID_SHOULDER_HALF_WIDTH` удалены (ширина измеряется, а не
  фиксируется).
- `DM_GRID_HEX_SIZE = 0.5` — циркумрадиус гексагона соты (укрупнён с 0.33); заменяет
  устаревший `DM_GRID_CELL_SIZE = 0.66`.
- `DM_GRID_RAY_TOP = 2.0` / `DM_GRID_RAY_BOTTOM = 0.3` — вертикальный луч в O.
- `DM_GRID_RAY_HORIZ_HEIGHT_BEG = 0.5` / `_END = 0.2` — косые горизонтальные лучи.
- `DM_GRID_RAY_INTERSECT = ObjIntersectGeom` — тип всех лучей детектора.
- `DM_GRID_CLEAR_ROWS = 10` — «чистых» рядов после первого RED до остановки роста сетки.
- Удалены (устарели): `DM_GRID_RAY_BODY_HEIGHT`, `DM_GRID_RAY_BOTTOM` (старый смысл),
  `DM_GRID_GROUND_NORMAL_EPS`, `DM_GRID_OBSTACLE_EPS`, `DM_GRID_RAY_HEIGHT`, `DM_GRID_SCAN_MIN_DIM`,
  `DM_GRID_RAY_RADIUS`, `DM_GRID_GROUND_EPS`; метод `ScanEntities` (сканбокс) удалён целиком.
- Удалены (v3.279): `DM_GRID_ROAD_HALF_WIDTH`, `DM_GRID_SHOULDER_HALF_WIDTH` — полуширина
  территории теперь измеряется (`dmRoadProbe.RoadWidth`), а не фиксируется.
- Удалены с A*/BFS (v3.278): `DM_GRID_ASTAR_NODES_PER_TICK`, `DM_GRID_INF`,
  `DM_GRID_WIDTH_CELLS`, `DM_GRID_CELL_SIZE` — pathfinding больше не A* (граф-алгоритм, §7).
