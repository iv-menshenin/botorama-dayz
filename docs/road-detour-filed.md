# Объезд препятствий (road detour) — полевая записка

> Только про объезд препятствий водителем: план, архитектура, что сделано, что осталось,
> какие проблемы встретили. Актуально на v3.259. Пишется как хендофф, чтобы не
> переоткрывать известное заново.

---

## 1. Цель

Бот-водитель едет по дорожному графу и должен **объезжать препятствия** на дороге:
бетонные ограждения, остовы машин, контейнеры и т.п. На тестовом участке это
**комплексное поле препятствий на ~100 м** (несколько ограждений + остовы + контейнер
подряд). Задумка: сначала **коробка** (узкий одиночный манёвр), если не влезает —
**соты** (грид, обойти весь комплекс по найденной траектории).

Ключевое требование заказчика (дословно):
> сначала прямоугольник (бокс), потом соты — **всё это время бот должен снижать скорость
> вплоть до остановки**; только если **и прямоугольник и соты дадут FAIL**, бот сдаётся
> и выходит — но **скорость машины должна быть равна нулю**. Если препятствие есть, а
> маршрута ещё нет — бот должен **тормозить**.

## 2. Архитектура (два уровня)

Всё живёт в `src/core/4_World/Entities/Bot/Intent/dmBotIntent_Drive.c` (интент вождения)
и `src/roads/4_World/Pathfinding/dmRoadHoneycomb.c` (соты).

### Поток (интент вождения, `TickDriving`)

1. **`TickDetect`** — вперёд-райкаст на высоте корпуса (`RaycastHits`, `ObjIntersectGeom`,
   `CollisionFlags.ALLOBJECTS`) детектит препятствие. Фильтр: свой кузов/водитель
   (`pIgnore=m_Car` + `hit.obj/parent == m_Car || driver`), земля (`obj==null && dir[1]>EPS`
   — нормаль вверх), кусты (`IsBush`). Препятствие = `obj` с горизонтальной нормалью.
   Ставит `m_DetourActive` + `m_DetourBrakeTimer`.
2. **`PerformDetour`** — бокс: пробует 7 полос (`RaycastHits` по полосам), если есть
   чистый коридор нужной ширины — вставляет коробку `boxA..boxE`. Если коридора нет
   (`no clear corridor`) — переходит в **соты** (`m_HoneyState = 1`).
3. **`TickHoneycomb`** — соты считаются асинхронно; на это время бот **жёстко тормозит
   до нуля** (нейтраль + `DM_DRIVE_HARD_BRAKE=1.0`, `m_SpeedLimit=0`). По `DONE` →
   `InsertHoneycombPath`, по `FAILED`/вырожденному пути → `Fail` **только при скорости
   ≤ `DM_DRIVE_EXIT_MAX_SPEED` (2 км/ч)**.
4. **`InsertHoneycombPath`** — срезает хвост маршрута с текущего индекса, вставляет путь
   сот, **ре-снэпает роутер** `dmRoadRouter.Setup(дальняя_точка_сот, m_TargetPos)` (иначе
   роутер исчерпан ещё на первом рефилле и интент финиширует на хвосте обходного пути).

### Соты (`dmRoadHoneycomb`)

- **Территория**: сетка `m_RowCount × m_Width` (110 × 31), ячейка `DM_GRID_CELL_SIZE=0.66`,
  т.е. ~72.6 м вдоль направления дороги (`m_Dir`) × ~20 м поперёк (`m_Side`).
- **Origin** — НЕ центр машины, а **бампер + радиус капсулы**:
  `carPos + carDir * DM_DRIVE_HONEY_ORIGIN_OFFSET (3.5 = нос 2.0 + радиус капсулы 1.5)`,
  вдоль реального курса машины (`carDir`). Кузов остаётся позади территории.
- **Пайплайн** (`Tick`): `STATE_COLORING` (`ColorRow`/`ColorCell` по `DM_GRID_ROWS_PER_TICK=3`
  ряда за тик) → `STATE_MARK_SAFE` (`MarkSafe`) → `STATE_PATHFINDING` (`FindGoal` +
  `FindPathAStar`) → `SmoothPath` (string-pulling).
- **Раскраска клетки** (`ColorCell`): `groundY` = среднее `GetGame().SurfaceY()` по 4 углам.
  Затем `RaycastBlocked` — **горизонтальный луч вперёд** по `m_Dir` на высоте
  `DM_GRID_RAY_BODY_HEIGHT=0.3` (середина низкого барьера), радиус
  `DM_GRID_RAY_RADIUS=1.5` м. RED = хит с **горизонтальной нормалью**
  (`!obj && dir[1] <= DM_GRID_GROUND_NORMAL_EPS=0.7`); земля (`dir[1]>0.7`) пропускается.
  `pIgnore=m_CarObj` + ручной фильтр `obj/parent == m_CarObj/m_DriverObj`.
- **Адаптивный рост** (`TickColor`): после первого RED (`m_SeenRed`) сетка растёт ещё
  `DM_GRID_CLEAR_ROWS=10` «чистых» рядов и останавливается («дорога снова свободна»).
- **Goal** (`FindGoal`): самый глубокий вейпоинт маршрута внутри территории, снэпнутый к
  ближайшей SAFE-клетке; старт — `FindNearestSafe(0,0)`.

## 3. Что сделано (работает)

- **Детект препятствий** — вперёд-райкаст с нормаль-фильтром (земля/куст/свой кузов).
- **Бокс-объезд** — на HescoBox и ВПП подтверждён E2E.
- **Соты** — асинхронный грид: раскраска → mark-safe → A* → сглаживание.
- **Гейт интента убегания за рулём** — `EscapeDanger`/`EvadeAim` в `dmAISurvivor.c`
  заблокированы, пока `m_Pawn.IsInVehicle()` (иначе прицел игрока выбивал водителя из кресла).
- **Тормоз до нуля во время сот** — нейтраль + `DM_DRIVE_HARD_BRAKE`.
- **Гейт высадки по скорости** — `Fail` только при `speed ≤ 2 км/ч` (обе ветки: `IsFailed`
  и «вырожденный путь»).
- **Origin от бампера** — соты не бьют по собственному кузову.
- **Детект грани по нормали** — горизонтальный луч ловит вертикальную грань барьера.
- **Ре-снэп роутера** — маршрут продолжается к цели после обходного пути.

## 4. Проблемы и как решены (хронология)

1. **Водитель «исчезал»/высаживался при прицеле игрока.** Причина: `dmVision` ловил прицел →
   `EvadeAim()` создавал MOVE-интент (`dmBotIntent_EvadeAim` спринтует к укрытию), конфликт с
   командой транспорта выбрасывал водителя. **Фикс**: гейт `if (m_Pawn && m_Pawn.IsInVehicle()) return;`
   в `EvadeAim`/`EscapeDanger` (`2ff5c80`).
2. **Мотор «глох» на 43 км/ч** (и это сперва НЕПРАВИЛЬНО диагностировали как «сцепление/
   жёсткий тормоз» — пробовали нейтраль, тормоз 0.5, рестарт двигателя; всё мимо). Реальная
   причина: после вставки пути сот роутер был исчерпан (`refill +0 exhausted`), срабатывало
   условие финиша → `Finish` → `StopCar` (EngineStop) → высадка на ходу. **Фикс**: ре-снэп
   роутера + гейт высадки по скорости (`da67066`).
3. **Соты били по собственному кузову** (капсула 1.5 м стартовала из центра машины) → первые
   ряды RED → `m_SeenRed` рано → сетка гасилась на ~10 м, не доходя до барьера. Сначала
   пробовали исключить машину/водителя (`pIgnore` + фильтр `obj/parent`) — **не сработало**
   (хиты приходят с промежуточным collision-объектом). **Фикс**: origin от бампера (`f8193bf`).
4. **Барьер не красился RED** (вертикальная капсула). Причина: `SurfaceY` возвращает **верх**
   статического барьера, а не террейн → `groundY` = верх барьера → капсула не видит хит выше
   `groundY + EPS`; а крышка барьера имеет нормаль вверх (как земля), поэтому вертикальный
   луч по нормали не отличит её от земли. **Фикс**: горизонтальный луч вперёд по нормали грани
   (`5ca0596`).
5. **ТЕКУЩАЯ (не решена):** горизонтальный луч ловит препятствия (183 RED-клетки с
   `normalY≈0` на x∈[6936,6982]), но **адаптивный стоп** (`DM_GRID_CLEAR_ROWS=10` = ~6.6 м)
   гасит сетку на ~x=6989, **не доходя до следующей группы препятствий** (следующий
   `obstacle ahead` на x=6992). В итоге A* не видит сплошного поля → прямой путь → `path=2`
   (вырожденный) → высадка (корректно, на нуле).

## 5. Ключевые факты (чтобы не переоткрывать)

- Препятствия на участке — **статическая геометрия карты без scene-объекта**: рейкасты бьют
  их с `obj=null parent=null`, `scanbox` по той же области даёт 0 сущностей. Поэтому их
  нельзя фильтровать по `obj`/`parent` — только по **нормали поверхности** и высоте.
- `Game.SurfaceY(x,z)` возвращает **верх статических объектов** (барьера), а не «чистый
  террейн». Поэтому высотный детект «что выше groundY» с вертикальной капсулой не работает
  для низких статических барьеров.
- Препятствие — это **комплексное поле** (несколько ограждений + остовы + контейнер на
  ~100 м), а не одиночный объект. Соты должны обойти **все** их по одной траектории. Поэтому
  адаптивный рост сетки не должен резать территорию **между группами** препятствий.

## 6. Что осталось сделать

1. **Починить адаптивный рост сетки** так, чтобы территория покрывала **всё поле препятствий
   целиком** (с запасом), а не останавливалась после первой группы + `DM_GRID_CLEAR_ROWS`
   «чистых» рядов. Варианты:
   - увеличить `DM_GRID_CLEAR_ROWS` (10 → ~20+), чтобы «чистый» промежуток между группами
     (~10 м) не обрывал сетку; либо
   - останавливать рост только когда дорога чиста на заметно большем плече и маршрут уже
     вышел за последний RED-кластер; либо
   - (надёжнее) раскрашивать фиксированное число рядов (`DM_GRID_MAX_ROWS=110` = 72.6 м)
     и не гасить адаптивно, если это не дорого — поле ~100 м может потребовать больше 110
     рядов или повторный `Start` после проезда части поля.
2. **Проверить**, что A* при полностью раскрашенном поле строит объезд вокруг ВСЕХ
   препятствий (path ≥ 3 с дальней точкой за последним препятствием), а ре-снэп роутера
   ведёт дальше по дороге, а не разворачивается обратно.
3. **Рентген-проб** (опционально, если п.1 не даст результат): raycast/scanbox вдоль
   x=6984–6993, z=12675 — точно понять границы групп препятствий и почему последняя группа
   на x≈6992 не попадает в сетку.

## 7. Текущее состояние (на v3.259)

- Спек заказчика по **поведению водителя** выполнен: тормоз до нуля, высадка только при
  скорости ≈ 2 км/ч, гейт убегания, райкасты от бампера.
- НЕ выполнен **объезд**: соты на комплексном поле дают `path=2` (вырожденный), бот корректно
  сдаётся на нулевой скорости, но **не объезжает**. Блокер — адаптивный рост сетки (§6 п.1).

## 8. Релевантные константы

- `DM_DRIVE_NOSE_OFFSET = 2.0` — опорная точка вождения (нос).
- `DM_DRIVE_HONEY_ORIGIN_OFFSET = 3.5` — вынос origin сот (нос + радиус капсулы).
- `DM_DRIVE_HARD_BRAKE = 1.0` — полный тормоз в нейтрали при сотах.
- `DM_DRIVE_EXIT_MAX_SPEED = 2.0` — порог скорости высадки (км/ч).
- `DM_GRID_CELL_SIZE = 0.66` (ячейка), `DM_GRID_MAX_ROWS = 110`, `DM_GRID_WIDTH_CELLS = 30`.
- `DM_GRID_RAY_BODY_HEIGHT = 0.3` — высота горизонтального луча клетки.
- `DM_GRID_RAY_RADIUS = 1.5` — радиус капсулы луча клетки.
- `DM_GRID_GROUND_NORMAL_EPS = 0.7` — порог «нормаль вверх = земля» (cos 45°).
- `DM_GRID_CLEAR_ROWS = 10` — «чистых» рядов после первого RED до остановки роста сетки.
- `DM_GRID_OBSTACLE_EPS` / `DM_GRID_RAY_HEIGHT` — **удалены** (были для вертикальной капсулы).
