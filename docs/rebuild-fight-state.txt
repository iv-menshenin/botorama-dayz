Документ предлагает полностью переработать механику Fight состояния FSM бота

class dmBotState_Fighting:
    EntityAI m_TargetEntity             - это связь состояния и цели
    ref dmTarget m_Target               - это заполняется при входе, берем ссылку на цель в списке целей бота

    dmBotIntent_Approach m_IntentApproach
    dmBotIntent_Evasion m_IntentEvasion
    dmBotIntent_HitTo m_IntentHitTo

    Условие входа:
        Мы должны разработать единый арбитратор целей внутри бота
        т.к. выбор сражаться/сдаваться будет зависеть от личных качеств бота
        личных характеристик и уровней угрозы.
        Давай создадим у бота метод GetHostileTarget - который будет возвращать цель, которую надо поразить
        условие входа будет bot.GetHostileTarget() != NULL

    После ВХОДА:
    	запишем bot.GetHostileTarget() в m_Target и m_TargetEntity

    Алгоритм тика:
    	Нужно постоянно держать в актуальности несколько Intent:
    		Смотреть на врага: LookAt - критический, параллельный
    		Приблизиться к врагу: Approach (новый) с пороговым расстоянием равным дистанции удара
    		Уворот: Evasion (новый) если противник хочет ударить, для боя с зомби упрощенный
    		Удар: HitTo (новый) постоянное желание ударить

    	Проверять все время, что цель жива и актуальна таким образом:
    	Если цель НЕ жива или 1 раз в 5 секунд:
    		Проверять bot.GetHostileTarget() и если там другая цель, то пересоздавать все Intent на нее
    		Если там пусто, то ВЫХОД

    Условия выхода:
    	bot.GetHostileTarget() - пустое


class dmBotIntent_Approach: критический, параллельный
	float m_Distance - пороговое значение
	EntityAI m_TargetEntity

	Как работает:
		вычисляем дистанцию до цели с учетом Velocity цели (если есть)
		если она больше порогового значения - приближаемся к цели (пока расстояние не сократится до m_Distance)
		если меньше порогового значения, то смотрим отклонение:
		  меньше 20 сантиметров - ничего не делаем
		  больше 25% - приближаемся к цели.
		Получается, что
			Якорем будет точка по направлению следования к объекту (используя pathfinding) не доходя до объекта m_Distance

		для упрощения механики, можем не использовать pathfinding, если цель ближе 3 метров

class dmBotIntent_Evasion: критический, параллельный
	EntityAI m_TargetEntity

	Как работает:
		Пока идет кулдаун между ударами (1-2 секунды) бот должен выполнять увороты вправо/влево (и назад)
		Для игрока это механика выполняется с поднятыми руками IsRaised - шаг назад = блок, влево/вправо = уворот

class dmBotIntent_HitTo: критический, параллельный
	float m_Distance - пороговое значение
	EntityAI m_TargetEntity

	Как работает:
		Срабатывает если дистанция до цели не больше порогового значения
		Выполняет механику удара, следит за кулдауном удара, выбирает Heavy или Light
		Это управление рукопашным боем по сути

Добавление существ в список целей бота должно происходить не только из глобальных регистров существ, которые находятся рядом
но и из EEHitBy (событие получения урона от кого то) - обычно атакующего можно узнать из иерархии обхекта source
source.GetHierarchyRootPlayer() - это если игрок ударил чем-то, если удары наносит зомби или животное, просто source должно подойти
Если произошла атака и атакующего нет в списке целей, то добавлять автоматически и сразу ставить высокий статус Threat (0.8, если удар отбил меньше 30 хитов и 0.9 если больше)

GetHostileTarget метод у бота должен выбирать из списка целей все цели у которых Threat >= 0.5 (DM_ATTACK_THREAT_THRESHOLD)
Затем сортиовать их в порядке удаленности от себя
И брать самую ближайшую

нужен тест /test bot target:
  1. спавнит бота, показывает саммари, 5 сек тишины
  2. спавнит зомби, который бьет бота
  3. проверка GetHostileTarget() - должна указывать на этого зомби через секунду
  4. опустить хиты зомби до 0 - убить
  5. проверка GetHostileTarget() должна вернуть пусто через 1 секунду

 Давай делать так: у нас есть вижен, который актуализирует этот список, он так же может расчитывать и Velocity, но не для каждого объекта, а по запросу:
   первый запрос GetVelocity получает велосити цели и кеширует ее на время 50 миллисекунд
   следовательно, если за один тик нам надо

   Все алгоритмы, которым нужен этот показатель берут значение из dmTarget
