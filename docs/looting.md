# Лут и исследование (botorama)

Единый источник правды по системе лута. Заменяет и вбирает `docs/looting-and-exploration.md`
(черновик) и `docs/plans/looting-and-exploration.md` (proposal). Требования уровня «что должно
работать» — в `docs/requirements.md`, раздел «Лут».

## Принцип «человеческой модели»

Лут строится по «человеческой модели» (см. `AGENTS.md`): бот делает то, что сделал бы человек.
Никакой сложной математики — упорядоченный поток решений и замкнутый контур «попробовал → не
вышло → запасной вариант». Конкретно:

- увидел нужное → пошёл;
- на месте — **по порядку** решил, куда положить;
- не хватает места → **репак** (выложить → отсортировать → собрать обратно);
- всё равно не вышло → **игнор** вещи (не зацикливаться).

## Слои

1. **Доменные провайдеры** (чистые, только хранят состояние и отвечают на вопросы, никого не
   пишут):
   - `dmLoot` (статик) — классификация + определение места + инвентарные примитивы + сборка
     фреймов. Лут-движок: зависит от `dmInventoryFrames`, **НЕ** от `dmRequirements`/`dmWishlist`.
   - `dmWishlist` — реестр желаний + скорер (`CalcDesired`, `SetDesired`, `SetJunk`, `Ignore`).
   - `dmRequirements` — анализатор инвентаря: индексы необходимости, `GetDiscardOrder`, `IsFull`.
   - `dmExplorer` — состояние мира: здания, флаг «посещено», период забывания.
2. **Координатор** — `dmNeeds`: переводит инвентарь в желания (нет оружия → желание оружия и т.п.).
3. **Поведение** — `Exploration` (состояние) + `PickUp` (интент, высокая логика) + `LookAround`.

## Классификация (`dmLoot.GetCategory`)

`FOOD`, `WEAPON`, `MELEE`, `MAGAZINE`, `AMMO`, `CLOTHING`, `REPAIR`, `MEDICAL`, `OTHER` — по
ванильному наследованию (`IsInherited(Edible_Base)`, `IsWeapon()`, `IsMeleeWeapon()`,
`IsMagazine()`, `IsAmmoPile()`, `IsClothing()`, `WeaponCleaningKit`/`SewingKit`/`DuctTape`,
`BandageDressing`).

## Поток подбора (согласован)

1. **Скан** (`ScanNearbyItems`) → предметы, которые бот **хочет** (`CalcDesired > порог`), с
   грубым пред-фильтром `CanCarry` (чтобы не идти к заведомо невместимой вещи).
2. **Идти** к предмету (`PickUp`, EXCLUSIVE).
3. **На месте** — определение места, строго по порядку:
   a. **Аттачмент-слот** (`FindAttachmentSlot`): оружие/мили → SHOULDER/MELEE/руки; одежда →
      свой слот (надеть). Если слот занят — оружие/мили кладётся в инвентарь (карго).
   b. **Карго** (`FindCargo`): свободное место в карго **всего** одетого инвентаря (не только
      рюкзак).
   c. **Эвакуация-репак** (см. ниже).
   d. Нет места → **игнор** (`Wishlist.Ignore(item)`).
4. Место определено → строятся и запускаются `dmInventoryFrame`-цепочки **параллельно**
   (многократный `Enqueue`, НЕ `Then`/`SuccessOnly`) — фейл одного шага **не прерывает** процесс.
5. Каждое решение логируется под единым префиксом `[Loot]` (стандартизировать `[LOOT]` → `[Loot]`).

## Эвакуация-репак (умная дефрагментация)

Вызывается под **конкретный предмет** (это НЕ «инвентарь заполнен»). Живёт в `PickUp`-интенте
(высокая логика, знает пешку; `dmLoot` поэтому не зависит от `dmRequirements`):

1. ДО операции взять `Requirements.GetDiscardOrder()` — предсортированный список «на выброс»
   (по возрастанию индекса необходимости: самое ненужное первым). Без перебора инвентаря.
2. Выложить все вещи на пол фреймами (физический дроп, `DropItem`).
3. Новую вещь добавить в **конец** списка.
4. Собрать вещи с пола **с конца** списка (новая первой → нужное → ненужное) фреймами.
5. Вещь не влезла → стоп; все оставшиеся → игнор-лист.

Обе процедуры — без пути-отката (бот уже у предмета).

## Инвентарные примитивы (`dmLoot`, статик)

- `TakeIntoCargo(pawn, item, to = null)` — `to` **опционален**: при `null` пешка сама ищет
  свободное место (`FindDestination`: аттачмент → карго).
- `TakeToHands(pawn, item)`.
- `TakeToAttachmentSlot(pawn, item, slotId)`.
- `TakeIntoDestination(pawn, item, dst)`.
- `InventoryChangeClothes(pawn, item)`, `InventoryMoveCargo(pawn, from, to)`.
- `DropItem` — остаётся `override` на пешке (ванильный контракт `PlayerBase.DropItem`), `dmLoot`
  зовёт `pawn.DropItem`.

Интенты обращаются к `dmLoot`, а не к пешке напрямую — единое место всей инвентарной механики.

## Wishlist (реестр желаний)

- `SetDesired(itemClass, necessity)` / `RemoveDesired` — уровень потребности (0..1), `itemClass`
  может быть базовым (наследование).
- `SetJunk(itemClass)` — «отвращение» (не трогать).
- `Ignore(item)` / `Unignore(item)` — игнор конкретной вещи (с таймаутом авто-Unignore ~5 мин).
- `CalcDesired(item) → 0..1` — скорер: ignored → 0; junk → 0; desired → значение; иначе fallback
  (калибр под своё оружие, одежда лучше надетой и т.п.).

## Requirements (анализатор инвентаря)

- `Update()` (тик ~5 с): проставляет каждому предмету **индекс необходимости**:
  - базовый по категории: FOOD=1, WEAPON=0.9, MELEE=1, MAGAZINE=1, AMMO=1, CLOTHING=0.5,
    REPAIR=0.7, MEDICAL=1, OTHER=0.5; патроны под свой калибр — всегда 1 (не деградирует);
  - n-й предмет категории получает `base / 2^(n-1)` (дубликаты дешевле).
- `GetDiscardOrder()` — предметы по возрастанию индекса (первый = выбросить первым).
- `IsFull()` — занято > `DM_LOOT_FULL_THRESHOLD` (0.75) ёмкости.
- Отдельно: `GetRuined()` (разрушенные — выбросить сразу), `HasKnife()`, `HasDamagedWeapon()`,
  `RequireToRepair()` (пара «повреждённое + инструмент»).

## Explorer (состояние мира)

- `OnUpdate()` (раз в минуту): здания в радиусе 50 м, флаг «посещено», привязка предметов к
  зданию (у предмета флаг «проверено»).
- Забывание: здание дальше 500 м — забыть; не посещённое и дальше 200 м — забыть.
- `GetNearest(radius)` — ближайшее непосещённое здание (фильтр «есть лут»).

## Интенты / состояния

- **`PickUp`** (EXCLUSIVE): маршрут к предмету → на месте — решение (аттачмент → карго →
  эвакуация → игнор) → цепочки фреймов. Блокировка входа: нет места.
- **`LookAround`**: маршрут по зданию; при предмете ближе 3 м — проверить «нужность» (Wishlist →
  классификация), взять нужное.
- **`Exploration`** (состояние): дефолт — блуждание к непосещённым зданиям (`Explorer.GetNearest`)
  + осмотр (`LookAround`) + оппортунистический подбор (`PickUp` при `CalcDesired > порог`).
