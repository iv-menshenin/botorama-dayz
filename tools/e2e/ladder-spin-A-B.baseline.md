## Сценарий A — один спуск без подъёма (КЛЮЧЕВОЙ)

Таймлайн (RPT):
```
19:45:27 Spawn() position=<13735.26, 209.12, 12967.29> orientation=<0,0,0>   ← на крыше
19:45:34 [E2E] step 2 moveto (вниз)
19:45:34 UseLadder.start dir=-1 entry=<13735.49, 208.93, 12967.05>
19:45:34 UseLadder: attach orient=-61.5258 index=1 type=metal
19:45:37 UseLadder.detach orient=-48.6353 bodyYaw=-48.6353                    ← отцепка (спуск ~3с)
19:45:42 … RAW heading начинает накручиваться                                ← накрутка
19:46:20 snapshot Pos=<13744.82, 205.99, 12961.62> (земля, дошёл)
```

1. **Калибровка ДО спуска** (бот стоит на крыше, 19:45:28–33): `heading=0 orient=0` — чистый,
   накрутки нет. ✓
2. **В фазе спуска** (19:45:35–36): `heading≈+113.65`, `orient≈−48.63` →
   **heading − orient = +162.26°**.
3. **Сразу после отцепки** (19:45:37) и до ~19:45:42: корпус доворачивается к цели внизу,
   heading следует за orient с постоянным сдвигом **+162°** (кадры не накручиваются).
4. **Накрутка стартует в 19:45:42** (~5 с после отцепки, ~3 с после истечения 2-с grace):

```
19:45:42 RAW: heading=469.291 orient=155.541
19:45:42 RAW: heading=587.983 orient=114.869
19:45:42 RAW: heading=750.261 orient=117.519
19:45:42 RAW: heading=912.538 orient=125.42
19:45:42 RAW: heading=1074.82 orient=135.19
19:45:42 RAW: heading=1237.09 orient=145.627
19:45:42 RAW: heading=1399.37 orient=156.301
19:45:42 RAW: heading=1561.65 orient=167.059
…wrap → 248.48 → 410.76 → 573.04 → 735.32 → 897.59 → 1059.87 → 1222.15…
```
→ **~162°/кадр**, линейно, с момента 19:45:42. При этом `headingDiff` заморожен на
`2.83228 рад` (=162.26°), `bodyYaw` монотонно растёт ~6.8°/кадр (видимый спин корпуса).

## Сценарий B — подъём/спуск №1, потом попытка цикла №2

Таймлайн (RPT):
```
19:50:32 UseLadder.start dir=1  (подъём №1)  attach orient=133.025
19:50:37 UseLadder.detach orient=-48.6351    (подъём №1 завершён)
19:50:48 UseLadder.start dir=-1 (спуск №1)   attach orient=-45.6987
19:50:51 UseLadder.detach orient=-48.6351    (спуск №1 завершён)
19:50:56 RAW heading накручивается (h=436.7) ← накрутка после спуска №1
19:51:13 moveto вверх (цикл №2) → бот ЗАСТРЯЛ, лестницу не достиг (нет UseLadder.start)
19:51:55 snapshot Pos=<13743.26, 206.01, 12960.02> (земля)
```

1. **Подъём №1 (dir=1)** — СИММЕТРИЯ СЛОМАНА: на лестнице `heading = orient = −48.6351`
   (выровнены, **без 162° сдвига**). Т.е. сдвиг 162° — артефакт ТОЛЬКО спуска (dir=-1).
2. **Спуск №1 (dir=-1)** — снова `heading=+113.643, orient=−48.6351` (сдвиг +162°).
3. **Накрутка после спуска №1** стартует в 19:50:56 (тоже ~5 с после отцепки 19:50:51):
```
h=436.707 → 415.961 → 578.239 → 740.516 → 902.794 → 1065.07 → 1227.35 → 1389.63 →
1551.9 → 1714.18 → 1876.46 → wrap → 401.015 → 563.292 → 725.57 → 887.848 → 1050.13 → 1212.4 …
```
   та же скорость ~162°/кадр.
4. **Цикл №2 НЕ выполнен**: после спуска №1 бот закрутился и не смог снова полезть.
   `MV: laddering=false` всё время, `vel` дёргается (осцилляция на месте), `headingDiff=2.83228`
   заморожен (216 кадров), heading продолжает накручиваться (211 кадров `|h|>360` в окне
   19:51:14–19:51:30). До лестницы не дошёл → спуска №2 нет.

## КЛЮЧЕВЫЕ выводы

1. **Накручивается ли heading от одного спуска БЕЗ подъёма?** — **ДА.** Спуск (dir=-1) сам по
   себе даёт сдвиг `heading−orient = +162.26°`, который через ~5 с после отцепки превращается в
   линейную накрутку **~162°/кадр** (сценарий A, без какого-либо предварительного подъёма).

2. **Накапливается ли накрутка между спусками?** — **Не удалось измерить**: после спуска №1 бот
   закручивается и **не может продолжить маршрут** (не залезает на цикл №2). Т.е. одного спуска
   уже достаточно, чтобы сломать маршрут — «накопление между спусками» не возникает, т.к. второй
   спуск недостижим.

3. **С какого момента накрутка?** — **НЕ в фазе подъёма/спуска** (там heading либо выровнен при
   dir=1, либо заморожен на +162° при dir=-1, но не растёт) и **НЕ в момент отцепки**. Накрутка
   начинается **~5 с после отцепки**: ~2 с grace (heading выровнен) + ~3 с доворот корпуса к цели,
   после чего замороженный `headingDiff=2.83 рад` перехватывает управление и накручивает heading.

**Симметрия (корневая подсказка для фикса):**
- подъём dir=1 → `heading == orient` (без сдвига);
- спуск dir=-1 → `heading == orient + 162.26°` (= 2.83228 рад).
Т.е. сдвиг вносится именно командой спуска (`HumanCommandLadder` на dir=-1 / `IntentMove(180)`).

**Статус текущего фикса (normalization + grace):** **НЕ лечит** — он лишь ОТСРОЧИЛ накрутку
на ~5 с (grace 2 с + доворот). Сырой heading всё равно накручивается, корпус всё равно крутится
(`bodyYaw` монотонно растёт, `headingDiff` заморожен на 2.83 рад). Баг воспроизводится.
